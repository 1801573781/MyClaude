# ADR-0006：PPTX 克隆引擎的结构守恒守卫（对齐/居中/单行）

## 背景（479 反馈三问题）

| 问题 | 现象 | 根因层次 |
|------|------|---------|
| P.2 目录不居中 | 4 条目组整体偏上 0.99cm | **结构删减后未重排**：模板 5 条删 1 条，剩余组沿用原坐标 |
| P.8 "02"不居圆 | 方块偏上 0.91cm | **模板原生缺陷带入**：克隆照搬坐标，无"装饰-编号"关系校验 |
| P.9 金句碎行 | 一句被切三段 | **填充策略与槽宽脱钩**：12 字硬切不感知槽实际宽度 |

三问题同源：**引擎只做"内容替换"，不做"结构守恒"**——删/改内容后，页面几何关系（居中/对齐/单行性）失去了模板原设计。

## 决策：三层守恒守卫

### 1. 删减重排（shifts 机制）— template-clone.ts fillToc + PYTHON_CLONE
- TS 侧：条目少于模板时，生成 `shifts`（槽位→平移量），目标=原全量跨度中心
- Python 侧精确锚定：目标中心优先取页面**最大无文本装饰形状**（目录大圆等视觉锚），排除面积>60%页面的背景、宽高比>1.8 的扁宽/竖幅形状；无锚时回退 TS 估算
- 平移作用于槽位所属**顶层形状**（组合整组移动，编号/图标/圆角矩形同步）

### 2. 对齐守卫（align_guard）— PYTHON_CLONE 页级全量
- 启发式：纯数字/百分比编号框 ↔ 最近的大装饰形状（≥1.2 倍编号框、中心距 <2 倍编号框宽）应垂直居中
- 偏差 >0.5cm（180000 EMU）才修正——排除模板故意的视觉微调
- 只处理顶层形状（组合内子形状坐标系不同，不可跨系比较）

### 3. 单行优先（fill_tf 单行模式）— PYTHON_CLONE
- 无换行文本：若 `可用宽 / 单字号宽 ≥ 11pt`，直接缩号单行，禁用 wrap-first 折行
- **"能单行就单行"**：金句/标题/短句天然受益；长正文 need_sz<11 自然走折行不受影响
- 与既有 wrap-first（正文可读性优先）正交：单行可行性判定在前，折行兜底在后

### 附：金句切段宽度自适应（fillQuote segLimit）
- 窄卡槽维持 12 字保守；宽主槽按 `槽宽×72×0.92/22pt` 自适应上限，宽槽整句单段

## 验证

- **纯 python 链路端到端**（从 TS 源提取 PYTHON_CLONE/PYTHON_SCAN 字符串直驱，绕开 vitest 包装与 node driver），产物 python-pptx 断言 + 几何落盘 JSON 双重核验，三场景全 PASS：
  - TOC 4 条目组与大圆中心差 0.000cm（+0.987cm 平移精确命中）；05 组整组删除无残留；未删组（01-04）坐标原样保留
  - 02 方块与最近装饰圆中心差 0.000cm（+0.912cm 修正）；01/03 原本对齐的方块未被误动（0.5cm 阈值防误伤验证）
  - 金句 21 字整句单行完整无碎段
- tsc 全量类型检查通过

### 验证方法论沉淀（踩坑记录）

- **提取法转义陷阱**：从 TS 源正则提取内嵌 python 模板字符串时，TS 字面 `\\d`/`\\n` 直接写入 .py 会多一层转义（`r'^\\d'` 匹配字面反斜杠 → num_guard/align_guard 全失效）。生产链路（JS 求值后写入）无此问题。验证环境必须还原 JS 求值语义：`text.replace("\\\\", "\\")`
- **bash/file_view 结果甄别**：噪声环境下的输出不可尽信，关键断言必须**落盘 JSON + file_view 交叉核验文件真实存在性**；“路径不存在”错误可证伪此前读取结果的真实性

## 后果

- 正面：模板原生缺陷（如 T29 页 02 偏上）在克隆产物中自动矫正；目录删条后自动居中；短句不再被无意义折行
- 负面/权衡：anchor 启发式（最大紧凑装饰）在无装饰锚的极简页面退化为 TS 估算（跨度过半致偏差 <0.3cm，可接受）；align_guard 的 1.2 倍/2 倍距离阈值是经验值，极端密集装饰页可能选错锚（偏差阈值 0.5cm 兜底不至于劣化）
- 后续：Verifier 可加"产物几何断言"复用本守卫的检测逻辑（检测-修复同源）
