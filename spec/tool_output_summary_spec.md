# 需求文档：工具返回摘要优化（纯需求版）

## 1. 背景与目标

当前 MyClaude 在执行 `<create>` 和 `<str_replace>` 工具后，系统会将整个文件内容（或修改后的完整文件）作为工具执行结果返回给 LLM。这导致对话上下文迅速膨胀，尤其是生成或修改大文件时，单次操作消耗大量 token。

**目标**：
- 将 `<create>` 和 `<str_replace>` 的返回内容从“完整文件内容”改为 **“摘要 + 简略信息”**，显著降低上下文占用。
- 要求 LLM 在调用 `<create>` 时主动提供一句话摘要（不超过 50 字符），系统只返回该摘要及文件路径、大小等元信息。
- 对于 `<str_replace>`，系统自动生成摘要（如“在 {path} 中替换了 1 处，{old_len} -> {new_len} 字符”），不再返回修改后的完整文件内容。
- 保持对现有文件写入/修改的完整性和正确性（文件内容仍然全量保存/实际替换）。
- 保持向后兼容：若 LLM 未提供 `<create>` 的摘要，系统返回简略信息（路径 + 字符数）。
- 本次需求**必须实现** `<create>` 和 `<str_replace>` 的摘要返回，不作为可选扩展。

## 2. 功能需求

### 2.1 修改 `<create>` 工具协议

- **原协议**：`<create path="绝对路径">完整文件内容</create>`
- **新协议**：`<create path="绝对路径" summary="一句话摘要（不超过50字符）">完整文件内容</create>`
  - `summary` 属性为**建议提供**（系统允许缺失，用于向后兼容）。
  - 摘要应简要描述文件的主要作用，不换行，不含双引号。
- **系统行为**：
  1. 正常将 `完整文件内容` 写入磁盘（与原有逻辑一致）。
  2. 返回给 LLM 的结果中**不再包含文件内容**，改为：
     - 如果 LLM 提供了 `summary`：返回字符串 `[create] 文件已创建：{path}，摘要：{summary}`
     - 如果未提供 `summary`：返回字符串 `[create] 文件已创建：{path}（{字符数} 字符）`
  3. 返回结果中不包含文件内容本身。

### 2.2 修改 `<str_replace>` 工具协议

- **原协议**：`<str_replace path="绝对路径"><old>旧片段</old><new>新片段</new></str_replace>`
- **新协议**：**协议本身不变**（不需要增加属性），但系统返回给 LLM 的结果需要改为摘要形式。
- **系统行为**：
  1. 正常执行替换操作（与原有逻辑一致：读取文件、执行替换、写回磁盘）。
  2. 返回给 LLM 的结果改为摘要，格式为：  
     `[str_replace] 文件已修改：{path}，替换了 {count} 处（{old_len} → {new_len} 字符）`
     - `{count}`：实际发生替换的次数（当前实现为 1 次，未来若支持全局替换则动态变化）。
     - `{old_len}`：`<old>` 片段的长度（字符数）。
     - `{new_len}`：`<new>` 片段的长度（字符数）。
  3. 若替换失败（如 `<old>` 未找到或文件不存在），返回原有错误信息（不缩短），例如：`[str_replace] 修改失败：未找到精确匹配片段` 或 `[str_replace] 错误：文件不存在`。

### 2.3 解析逻辑修改

- 更新 `<create>` 的正则表达式，使其能够捕获可选的 `summary` 属性。
- 在生成的工具参数字典中，为 `create` 增加 `"summary"` 键（若未提供则为空字符串）。
- `<str_replace>` 的正则无需修改。

### 2.4 执行逻辑修改

- **`create` 分支**：调用 `file_create` 写入文件后，根据参数中是否有非空 `summary` 来构造不同的返回字符串。若 `summary` 长度超过 50 字符，则自动截断至 50 字符并添加 `…`。
- **`str_replace` 分支**：调用 `file_str_replace` 执行替换后，根据返回结果是否以“已修改”开头判断成功与否。若成功，则生成包含文件路径、替换次数、新旧片段长度的摘要字符串；若失败，则原样返回错误信息。

### 2.5 涉及文件清单

为实现上述需求，需要修改以下 MyClaude 项目文件：

- `src/message/sys_prompt.md`：更新 `<create>` 和 `<str_replace>` 工具说明，告知 LLM 返回格式的变化以及 `<create>` 应提供 summary。
- `src/llm_tool/tool_executor.py`：
  - 修改 `patterns` 中的 create 正则，以捕获 summary 属性。
  - 修改 `parse_tools` 中解析 create 的逻辑，存储 summary。
  - 修改 `execute_code_tool` 中的 `create` 分支和 `str_replace` 分支，改为返回摘要。
- `src/llm_tool/file_tool.py`：**无需修改**（文件操作函数保持原样）。
- `src/query/query_loop.py`：无需修改。
- `src/query/session_log.py`：无需修改（日志仍记录返回的字符串，该字符串已变短）。

## 3. 单元测试要求

使用 `add_tests` Skill 为本次修改生成完整的单元测试，测试文件位置：`src/llm_tool/test_tool_output_summary.py`。必须覆盖以下场景：

- **正常 `create` + 提供 summary**：解析后参数中包含 summary，执行后返回的字符串包含“文件已创建：...，摘要：...”，且不包含文件正文。
- **`create` 无 summary 属性**：解析后 summary 为空，执行后返回简略信息（路径 + 字符数）。
- **`create` summary 超长截断**：提供超过 50 字符的 summary，返回时应截断至 50 字符并附加 `…`。
- **`create` 文件写入成功且内容完整**：执行后读取磁盘文件，验证内容与 LLM 提供的一致。
- **`create` 文件写入失败（如路径非法）**：返回错误信息应完整，不被摘要化。
- **`str_replace` 成功**：执行后返回字符串格式为“文件已修改：{path}，替换了 1 处（{old_len} → {new_len} 字符）”，不返回修改后的文件完整内容。
- **`str_replace` 失败（未找到 old 片段）**：返回原有错误信息（如“未找到精确匹配片段”），不被摘要化。
- **`str_replace` 目标文件不存在**：返回原有错误信息（如“文件不存在”）。
- **向后兼容性**：旧版系统提示词（create 不带 summary）不会导致程序崩溃，仍返回简略信息。
- **正则匹配正确性**：测试 create 标签中 summary 属性使用双引号、单引号、前后有空格等变体，确保能正确捕获 path 和 summary。

所有测试使用临时目录作为代码输出根目录，避免污染真实项目文件。

## 4. 验收标准

- [ ] 修改后的代码能正确解析带 `summary` 属性的 `<create>` 标签。
- [ ] `execute_code_tool` 中 `create` 分支返回给 LLM 的内容不包含文件正文，而是摘要或简略信息。
- [ ] `execute_code_tool` 中 `str_replace` 分支返回给 LLM 的内容不包含修改后的完整文件，而是格式化摘要。
- [ ] 磁盘上的文件内容与 LLM 提供的完全一致（create 写入正确，str_replace 修改正确）。
- [ ] 单元测试全部通过，覆盖上述所有场景。
- [ ] 旧版 LLM（create 不提供 summary）仍能正常工作，返回简略信息。
- [ ] 相关日志记录的内容随之变短，但仍可读。

## 5. 备注

- 本需求**不修改** `<file_view>` 的行为，它仍然返回完整文件内容，因为查看文件往往是调试所需。
- `<str_replace>` 的摘要中“替换了 1 处”是基于当前实现每次只替换第一次出现。若未来升级为全局替换，则摘要应动态反映实际替换次数。
- 本需求仅涉及返回内容的改变，不改变工具的实际功能（文件写入/修改仍完整执行）。
